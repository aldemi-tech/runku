## Runtime and isolation result

- Safe V8 remains available in every Environment. Full Node is an optional executor selected by
  `disabled`, `dedicated-host`, or `dedicated-worker`; `safe`/`node`/`hybrid` remain Release
  composition terms and OCI remains an artifact format.
- The separate profile dispatches exact Project, Environment, Release, request, invocation,
  function, deadline, and arguments through NATS JetStream to `runku-server full-node-worker`.
- The cell writes a canonical immutable manifest/artifact projection before moving Workspace HEAD.
  The worker mounts only that projection read-only plus its own disposable cache/scratch. It does
  not mount Product data, Platform Identity, database URLs, application keys, or secret files.
- The Docker overlay runs the worker from the same versioned server image with a separate cgroup,
  PID/memory/CPU bounds, read-only root filesystem, dropped capabilities, and independent restart
  lifecycle. This narrows blast radius but still shares the host kernel and is not a hostile
  multi-tenant boundary.
- The compact separate worker has no remote Environment configuration broker. Release admission
  therefore rejects Full Node Actions declaring `variable:NAME` or `secret:NAME`; Safe V8 retains
  configuration support and `dedicated-host` retains its current in-process broker path.
